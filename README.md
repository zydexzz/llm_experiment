# llm_experiment

Эксперимент: сколько токенов занимают тексты у разных токенизаторов.

- **tiktoken** (OpenAI): `cl100k_base` (GPT-4 / GPT-3.5) и `o200k_base` (GPT-4o и новее) — считаются локально.
- **Китайские открытые модели** (токенизаторы с Hugging Face): `Qwen/Qwen2.5-7B-Instruct` и `deepseek-ai/DeepSeek-V3`. Скачивается только небольшой файл токенизатора, веса моделей не нужны.
- **Claude**: официальный метод `client.messages.count_tokens` для моделей `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`, `claude-fable-5-2`.

## Что сравниваем

**Группа 1 — один текст на разных языках.** Три предложения о токенах (30–41 слово) в четырёх вариантах: английский, русский, казахский (кириллица) и казахский (латиница, транслитерация по таблице 2021 г.). Показывает, как язык и письменность влияют на число токенов.

**Группа 2 — реальные тексты, только русский, без перевода.** Показывает, сколько токенов занимает «живое» общение:

| Текст | Что это |
|---|---|
| Сообщение клиента | Короткое сообщение клиента (как есть, вместе с опечаткой) |
| Переписка менеджер–клиент | Диалог из четырёх реплик про семинар (как есть) |
| Код на Python | Небольшой рабочий фрагмент: расчёт предоплаты и вывод цен в тенге, комментарии на русском |
| Числа, даты, суммы | Сводка с датами, процентами и суммами в тенге |

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## Ключ Anthropic API

Для подсчёта токенов Claude нужен ключ. Он хранится в файле `.env`, который **не попадает в git** (он есть в `.gitignore`).

```bash
copy .env.example .env
```

Откройте `.env` и вставьте ключ после знака `=`:

```
ANTHROPIC_API_KEY=ваш_ключ
```

Не храните ключ в других файлах (например, `api-key.txt`): git их не игнорирует. Если ключа нет, скрипт всё равно работает — считает tiktoken, Qwen и DeepSeek и подсказывает, как добавить ключ. Для Qwen и DeepSeek ключ не нужен.

## Запуск

```bash
python token_count.py
```

Скрипт печатает все тексты, подробные таблицы для каждого токенизатора и три сводные таблицы. При первом запуске он скачивает с Hugging Face токенизаторы Qwen и DeepSeek (несколько МБ, дальше берутся из кэша); предупреждение Hugging Face об отсутствии `HF_TOKEN` можно игнорировать. К API Anthropic уходит около 36 запросов (по 9 на каждую модель Claude); `count_tokens` не генерирует текст, но на него действуют лимиты числа запросов. Если токенизатор не удалось получить, модель пропускается с пояснением.

## Выводы

### По группе 1 (языки и письменности)

1. **Английский везде самый «экономный».** У Claude русский текст занимает в 1,48 раза больше токенов, чем английский, а казахский — примерно вдвое больше (в 2,10 раза на кириллице и в 2,06 раза на латинице).
2. **У Claude кириллица и латиница для казахского почти не различаются:** 130 против 128 токенов (латиница на 1,5% короче). У tiktoken разница заметная и противоположная в двух кодировках: в `cl100k_base` латиница короче кириллицы на 40% (108 против 181), в `o200k_base` — длиннее на 29% (94 против 73). Qwen и DeepSeek ведут себя как `cl100k_base`: латиница короче кириллицы (105 против 145 и 104 против 127).
3. **Все четыре проверенные модели Claude дали одинаковые числа** на всех восьми текстах. Скорее всего, у них общий токенизатор, но это не проверялось на других моделях. Для этих образцов выбор модели на число токенов не влияет.
4. **Claude против OpenAI.** На английском Claude даёт больше токенов, чем обе кодировки tiktoken (62 против 45, на 38% больше). На русской прозе и казахской кириллице Claude лучше старой `cl100k_base` (92 против 105 и 130 против 181), но хуже новой `o200k_base` (92 против 61 и 130 против 73). Для казахской латиницы Claude уступает обеим кодировкам (128 против 108 и 94).
5. **Новая кодировка OpenAI сильно улучшила кириллицу:** переход с `cl100k_base` на `o200k_base` сократил русский текст с 105 до 61 токена, казахский на кириллице — со 181 до 73. На английском разницы нет (45 и 45).

### По группе 2 (реальные русские тексты)

6. **Живой русский текст у Claude дороже обычной прозы.** Он даёт 1,81–2,18 символа на токен, а русская проза из группы 1 — 2,84. То есть на каждый символ приходится больше токенов: от 23% (код) до 36% (числа и суммы). На слово выходит 2,9–4,1 токена (у прозы — 2,63).
7. **Дороже всего по символам — текст с числами и суммами** (1,81 символа на токен; 209 токенов на 378 символов). Вероятная причина — цифры, пробелы внутри чисел («100 000») и знаки «×», «=», но для Claude это предположение: разбиение на токены я не смотрел.
8. **Короткое сообщение клиента: 45 токенов текста, но реальный запрос будет на 8 токенов больше** (служебная добавка) — это 53 токена, и добавка составляет около 15% запроса. Для переписки из 252 токенов добавка — около 3%.
9. **На реальных текстах Claude близок к `cl100k_base` и заметно дороже `o200k_base`.** Относительно `cl100k_base` у Claude больше токенов на 7% (сообщение), 1% (переписка), 26% (код), 4% (числа). Относительно `o200k_base` — больше на 105%, 54%, 44% и 31%. Для русской переписки новая кодировка OpenAI заметно экономнее.
10. **По tiktoken нельзя оценивать токены Claude.** Например, для кода `cl100k_base` показала 172 токена, а Claude насчитал 217: оценка по tiktoken занизила бы число на 21%.

### Китайские модели (Qwen и DeepSeek)

11. **На английском Qwen и DeepSeek дают те же 45 токенов, что и tiktoken**, а Claude — 62. На русской прозе обе китайские модели экономнее Claude и `cl100k_base` (DeepSeek 68, Qwen 81 против 92 и 105), но уступают `o200k_base` (61). На казахской кириллице DeepSeek (127) на уровне Claude (130), Qwen (145) хуже; на казахской латинице обе (105 и 104) близки к `cl100k_base` (108) и лучше Claude (128).
12. **На живой русской переписке DeepSeek-V3 — второй после `o200k_base` по всем четырём текстам** (31, 194, 165 и 171 токен). Относительно Claude у него меньше токенов на 31%, 23%, 24% и 18%. Qwen2.5 меньше Claude на сообщении (33 против 45), переписке (225 против 252) и коде (178 против 217).
13. **На числах Qwen хуже всех: 229 токенов (1,65 символа на токен), больше даже Claude (209).** Причину я проверил на примере «Итого 2 815 000 тг»: Qwen разбивает число по одной цифре (`2`, `8`, `1`, `5`, `0`, `0`, `0`; всего 15 токенов в строке), а DeepSeek берёт группы по три цифры (`815`, `000`; всего 10 токенов). Поэтому на тексте с суммами DeepSeek (171) заметно экономнее Qwen (229).
14. **Из пяти токенизаторов Claude даёт больше всех токенов на пяти из восьми текстов:** английский, казахская латиница, сообщение клиента, переписка (там разница с `cl100k_base` всего 2 токена) и код. Это про число токенов, а не про качество или цену ответа.

### Как прикинуть стоимость переписки

- Для русской переписки с Claude ориентир: **около 2 символов на токен** и **около 3,6 токена на слово**.
- К каждому запросу прибавляйте около **8 токенов** служебной добавки.
- Пример: если отправлять в Claude диалог вроде приведённого целиком одним запросом, 1 000 таких диалогов — это 252 000 токенов текста плюс 8 000 служебных, то есть **около 260 000 входных токенов**. Умножьте на цену входных токенов за 1 млн из актуального прайса Anthropic (цена зависит от модели, а число токенов у четырёх проверенных моделей одинаково).
- Здесь не учтены системный промпт, история переписки (при каждом новом сообщении она отправляется заново) и ответ модели (выходные токены стоят дороже входных).
- Число токенов Qwen и DeepSeek — это только токены текста. Стоимость у их провайдеров зависит от своих тарифов; по числу токенов цену напрямую сравнивать нельзя.

## Оговорки

- **Это несколько коротких образцов**, а не статистика. Выводы — ориентир; на других текстах числа будут другими.
- **Тексты 1 и 2 из группы 2 — реальные сообщения, приведены как есть.** Код и сводка с суммами написаны мной: числа в сводке (47 участников, 2 815 000 тг и т. д.) **вымышленные**, они нужны только как пример текста с числами, датами и суммами. Арифметика в них сверена.
- **Для кода столбец «Слов» условный** (разбиение по пробелам), поэтому «токенов на слово» для кода сравнивать с прозой стоит осторожно.
- **Казахский текст составлен с помощью ИИ и не проверялся носителем языка.** Слов в вариантах группы 1 разное количество (41, 35, 30, 30), поэтому «токенов на слово» между языками сравнивать нельзя — для этого лучше смотреть на отношение к английскому или на «символов на токен».
- **Казахская латиница получена автоматической транслитерацией** по таблице 2021 г. ([Википедия](https://en.wikipedia.org/wiki/Kazakh_alphabets), апрельская редакция с `ñ`). У казахской латиницы было несколько редакций (2017, 2018, 2021); для другой редакции (например, с апострофами) числа для латиницы были бы другими. Таблицу я сверял по Википедии, а не по официальному документу.
- **Служебная добавка Claude вычтена приближённо.** `count_tokens` считает токены всего запроса, включая оформление сообщения. Добавка (8 токенов) определена как разница для запроса из одного символа «.» и 1 токена, то есть возможна ошибка в ±1 токен. Числа Claude в таблицах — это токены самого текста; в реальном запросе к ним добавляется эта добавка. Для tiktoken, Qwen и DeepSeek добавки нет (служебные токены начала текста не считаются).
- **Взяты токенизаторы конкретных моделей:** `Qwen/Qwen2.5-7B-Instruct` и `deepseek-ai/DeepSeek-V3`. У других версий этих семейств токенизатор может отличаться.
- **GLM-4 и Kimi не включены:** у них нет готового файла `tokenizer.json`, для их токенизаторов нужен собственный код из репозитория (`trust_remote_code`), и выполнять чужой код я не стал.
- **tiktoken — токенизатор OpenAI**, по нему и по токенизаторам китайских моделей нельзя оценивать токены Claude. Для Claude используйте `count_tokens`.
- Список моделей и числа актуальны на дату запуска (10.11.2026); токенизаторы моделей могут измениться.
